# Context Pack: CAP-001 Fixed-SLO Capacity Validation

## Gate

Requires completed service/load harness, frozen contract and dataset, dry-run
cloud lifecycle, and explicit approval for paid AWS execution.

## Task

Run the preregistered KleidiAI enabled/disabled capacity comparison on one
Graviton4 `c8g.4xlarge`, preserve all evidence, and issue pass, fail or
inconclusive without changing thresholds.

## Load These Files

- `docs/CAPACITY_VALIDATION.md`
- `docs/BENCHMARK_PROTOCOL.md`
- `docs/AWS_BUDGET.md`
- `docs/ESTABLISHED_EVIDENCE.md`
- accepted experiment JSON under `ops/experiments/`
- service/load harness source and tests named by the work item

## Trusted Inputs

- Accepted contract and schema-valid experiment record.
- Checksummed runtime/model artifacts.
- Tested lifecycle and cleanup code.

## Verify Before Acting

- Current AWS price and quota.
- Credential identity and permissions.
- Artifact availability and hashes.
- Runtime flags against the pinned runtime.

## Expected Outputs

- Complete raw evidence bundle.
- Claim ledger result for fixed-SLO capacity and Arm attribution.
- Spend and cleanup records.
- Updated registry, traceability and status.

## Non-Goals

- Search alternative parameters or instance types.
- Change the workload, SLO or threshold after seeing results.
- Add a weaker fallback story after failure.
- Build report UI during the paid session.

## Verification

- Five valid repetitions per treatment/mix.
- Enabled and disabled configuration diff contains only the KleidiAI control.
- `kai_*` positive/negative evidence is correct.
- Resource inventory is clean after termination.
- The result is reproducible from raw evidence.

## Stop And Ask

Stop for root credentials, hash mismatch, uncontrolled treatment differences,
quota/price changes, ceiling risk, missing cleanup or invalid repetitions.
